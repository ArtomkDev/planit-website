# Дизайн та взаємодія PlanIt

Авторитетний посібник для цього репозиторію. Оновлено 14.10.2026 після правок за візуальним відгуком; результати та межі перевірки — у `AUDIT.md`. Перед зміною інтерфейсу читати цей файл і відповідні локальні довідники `node_modules/next/dist/docs/`.

## Продукт та пріоритети

PlanIt допомагає студентам тримати розклад, завдання й матеріали разом. Сайт пояснює продукт, дає спробувати чотири локальні демо, відкриває застосунок і надає документи та підтримку. Сайт не зберігає демо у справжньому розкладі: пояснення під кожним демо має залишатися видимим.

Візуальна ідентичність: жирні компактні заголовки, спокійні нейтральні поверхні, рожевий акцент у світлій темі, м’ятний у темній, кольорові картки предметів та піксельні декоративні поля. Декорація підтримує зміст; вона не задає навігацію, не перекриває текст і не отримує фокус. Hero використовує оригінальну рухому піксельну анімацію `PixelDisplay` без додаткового opacity на wrapper: прозорість окремих пікселів визначає renderer. Не приглушувати її повторно під час загального UI-аудиту без запиту користувача.

Пріоритети: читабельний зміст → однозначна дія → доступна взаємодія → декоративний ефект. Зберігати зміст і можливості продукту. Не додавати другу навігацію до короткої послідовності лише для симетрії або анімації.

## Навігація

- `src/components/layout/Header.tsx` — єдине джерело груп «Продукт», «Документи», «Підтримка». Групи — кнопки розкриття; їхні елементи — посилання на адреси. Кнопка має `aria-expanded` і `aria-controls`.
- **Не повертати «Можливості» у глобальний header**, включно з мобільним меню. Це якір головної, а не група адрес. Посилання у футері залишається доречним.
- Desktop від `1024px`: три disclosure-кнопки. Натискання відкриває/закриває панель; Tab проходить її посилання; Escape повертає фокус на кнопку. Натискання поза header, вихід фокуса та перехід через breakpoint закривають меню. Не робити меню залежним від hover. Не застосовувати `role="menu"` без відповідної повної клавіатурної моделі.
- До `1024px`: одна кнопка меню та ті самі адреси з тієї самої конфігурації. Панель має власний вертикальний scroll і `max-height: calc(100dvh - 4rem)`. Це немодальна панель: без штучного блокування фокуса чи фонового вмісту.
- Поточне посилання позначається `aria-current="page"`; батьківська desktop-група — `data-active`. Не додавати активний стан усім посиланням схожого префікса.
- Web CTA відкриває застосунок у поточній вкладці; Google Play — у новій з `noopener noreferrer`; підтримка — `mailto:`. Адреси беруться з `src/lib/site.ts`: `APP_URL`, `PLAY_MARKET_URL`, `SUPPORT_URL`. `SITE_URL` використовується для canonical, sitemap, robots та social metadata, а не адреса застосунку.
- Зміна мови використовує `buildLocaleUrl`: зберігає шлях, query та hash; у Firebase action зберігає код і змінює `lang`, зокрема в `continueUrl`. Не збирати locale-URL вручну у звичайній навігації. 404 має власне перемикання поточної невідомої адреси.
- `/` одразу перенаправляє на `/uk` або `/en` без сторінки вибору: inline script у head виконує `location.replace` до hydration. Пріоритет — валідний `planit:locale` у localStorage, cookie `NEXT_LOCALE`, перша підтримувана мова з `navigator.languages`, українська за замовчуванням. Чинний `LocalePreference` запам’ятовує мову локалізованої сторінки. Query та hash зберігаються; явні `/uk` і `/en` не перенаправляються. Без JavaScript `noscript` meta refresh відкриває `/uk`. Це заміна статичного вибору за прямим запитом користувача від 18.10.2026; перевірка — поведінкові тести та виконання script із production export. Старі адреси документів перелічені у `firebase.json`; локальний preview читає цю саму конфігурацію.

Головна використовує звичайне прокручування: чотири самостійні статті з preview та editor. Вступ **не містить** рядка «Заняття / Оформлення / Завдання / Налаштування». Зберігати ID `features`, `feature-lesson`, `feature-appearance`, `feature-tasks`, `feature-schedule`, `platforms`. `DemoTabs` усередині editor — потрібні кнопки вибору режиму з `aria-pressed`, не секційна навігація і не ARIA tabs.

Окремий rail головної зараз не потрібний. Додавати локальну навігацію лише для обґрунтовано довгого матеріалу: збоку, вторинного вигляду, з читабельними посиланнями, правдивим активним станом, без перекриття вмісту. На телефоні залишати звичайний потік. Читач документів уже має локальний sidebar: потік до `1024px`, `position: sticky; top: 6rem` після цього, обмежений висотою контейнера документа. **Не замінювати його на viewport-fixed:** він перекривав футер.

## Розміри, відступи та типографіка

Реальні джерела: `src/app/globals.css`, `features/features.module.css`, `legal/LegalDocument.module.css`, `auth/AuthAction.module.css`.

| Правило | Реалізація |
| --- | --- |
| Header | `--header-height: 4rem`, `h-16`, sticky; внутрішній `max-w-7xl` |
| Основний marketing-вміст | `--content-width: 80rem` = `1280px`; `max-w-7xl`; бічний padding переважно `24px`, header `16px` на телефоні |
| Можливості | `1280px`; intro `780px`, опис `620px`; padding `110px 24px 64px`, на телефоні `76px 20px 40px` |
| Сітка демо | Дві `minmax(0,1fr)` колонки, gap `80px`, до `1024px` — `36px`; до `768px` — одна колонка, gap `24px` |
| Preview/editor | Preview максимум `360px`; editor максимум `420px`; body `480px`, на телефоні `clamp(280px,50svh,420px)` з власним scroll |
| Читач документів | Layout максимум `106rem` (`1696px`), article максимум `64rem`; desktop-sidebar `15–18rem`, gap `2rem`, від `1536px` `2.5rem` |
| Auth / останній CTA | Auth-panel `35rem`; CTA `max-w-5xl` (`64rem`) |
| Якорі | `--anchor-offset: 5.5rem` (`88px`), `scroll-margin-top` на ID; feature-статті `86px`; юридичні секції `7rem` (`112px`) |

Не додавати той самий відступ одночасно через `scroll-padding-top` і `scroll-margin-top`. Поточний глобальний `scroll-padding-top` дорівнює нулю.

Стандартні Tailwind-breakpoint: `sm 640`, `md 768`, `lg 1024`, `xl 1280`, `2xl 1536px`. Додаткові локальні: `380px` для icon-grid, `479px` для auth, `1920px` для декоративних карток у зовнішніх полях. Тестувати також `1023/1024px`, де змінюється модель header.

Шрифт — системний Tailwind `font-sans`, без завантаження стороннього webfont. Звичайний текст `14–18px`, line-height `1.5–1.85`. Marketing H1 на телефоні `clamp(2.5rem,6vw,3rem)`, на `640px` — `text-6xl`, на `768px` — `text-7xl`; weight `900`, tracking `-0.055em`, line-height `0.94`. Feature H2 `clamp(36px,4.8vw,60px)`, H3 на телефоні `34px`. Auth H1 `clamp(1.75rem,5vw,2.15rem)`. Одна H1 на сторінку; секції H2, можливості H3, назви editor H4, групи H5. Не створювати заголовок лише заради великого шрифту.

Використовувати наявні відступи `8/12/16/24/32/48px`; великі секції `64/96/110/128px` за зазначеними компонентами. Нові довільні значення мають пояснювати конкретний layout. Hero grid обов’язково має `minmax(0,...)`, текстова колонка — `min-w-0`; не приховувати intrinsic overflow через clipping.

`--brand-pink: #f45b8a`, `--brand-teal: #3ef7d2` — декоративні кольори. Не ставити білий текст на світлий м’ятний фон. Основний текст має контраст щонайменше `4.5:1`, великий — `3:1`, значущі контури й focus — `3:1`. Перевіряти фактичний фон, включно з прозорістю, а не лише hex із палітри.

`LessonCard` використовує `src/lib/card-contrast.ts`: темний foreground для світлого градієнта або білий із мінімальним чорним scrim. Перевіряється весь градієнт; підтримані кольори цього репозиторію — `#RRGGBB` та `hsl(H S% L%)`. Палітра демо міститься у `DemoPrimitives.tsx`; акцент взаємодії — `#2563eb`, не світліший blue для дрібного білого тексту. У tasks чорний scrim `20%` підтримує білий текст чинних двох градієнтів. При зміні палітри повторно перевіряти контраст.

Виняток від 14.10.2026 за прямим запитом користувача зі скриншотом картки: `LessonPreview` у двох демо явно задає білий `textColor`, зберігаючи початковий градієнт без scrim. Білий foreground поширюється на назву, час, тип, викладача, аудиторію та іконки. Цей вибір має пріоритет над автоматичним темним foreground і правилом 4.5:1 на світлих кольорах демо; автоматичний контраст інших карток залишається чинним. Перевіряти фактичний колір у світлій і темній темах та при зміні палітри.

Статус вебверсії використовує `text-brand-pink-strong` (`#b92f60` у світлій темі, `#f45b8a` у темній), узгоджений із рожевою поверхнею платформи. Загальний `brand-strong` для нього не підходить: у темній темі він м’ятний.

Active time chip має власний inverse background/foreground залежно від теми. Не перезаписувати його прозорим background звичайного chip; допоміжні labels картки мають непрозорий foreground, щоб не зменшувати розрахований контраст.

## Компоненти, стани та поверхні

- Marketing primary: заливка `site-text`, текст `site-bg`; secondary: border + нейтральна surface; tertiary: текстове посилання з focus. Одна домінантна дія на блок; store CTA поруч має другорядну ієрархію. Auth primary: `brand-strong` / `site-bg`. Editor primary: blue `#2563eb` / білий. Web platform використовує рожевий фон із темним текстом — свідоме розрізнення платформ, не шаблон для всіх кнопок.
- Посилання навігують; кнопки змінюють стан. Не ставити `cursor-pointer` та pressed-ефект на неактивну картку. `BentoCard` — інформаційна surface; її CTA залишається окремим посиланням. `LessonCard` із `onClick` підтримує Enter/Space; без нього не отримує button-role.
- `DemoFrame`, `SettingRow`, `SettingsGroup`, `DemoTabs`, `ChoiceList`, `LessonPreview` у `features/DemoPrimitives.tsx` — спільні примітиви. Драфт тримається в батьківському демо: зміна показується одразу; «Зберегти» оновлює saved; «Скасувати» відновлює saved; reset відновлює початковий приклад. Порожні/некоректні дані блокують save та дають конкретне пояснення. Успіх оголошується через `role="status"`.
- Форми мають label, відповідний тип input, зрозуміле пояснення валідації, `aria-invalid`/`aria-describedby` там, де є пов’язане повідомлення. У password-form visibility toggle — кнопка з accessible name і `aria-pressed`; submit disabled під час запиту, помилка — `role="alert"`. Валідація Firebase залишається відповідальністю SDK/сервісу.
- Legal reader: оболонка й документи відповідають `/uk` або `/en`, включно із заголовком, датою, `lang` та loading assets. Авторитетний текст — `PlanIt/content/legal/*.mdx` і `PlanIt/content/legal/uk/*.mdx`; сайт імпортує його через `legal:sync` без редагування перекладів. Manifest містить обидві локалі й SHA256, ключі loading cache включають мову. Skeleton прихований від assistive technology. Помилка локалізована, retry обходить кеш документа й manifest; звичайні запити поважають HTTP cache. Не маскувати помилку нескінченним skeleton. Не вставляти неперевірений HTML: використовувати чинний sanitizer, SHA256 та manifest.
- Legal prose переносить довгі текстові адреси через `overflow-wrap: anywhere`: переклади головного проєкту можуть містити URL як звичайний текст, а не посилання. Перевіряти overflow самого article та секцій, особливо на 360/390px.
- Cookie banner — немодальний `aside`, solid surface, рівнозначні accept/reject. Опис займає всю доступну ширину, кнопки на наступному рядку; на телефоні — колонка. Максимальна висота `calc(100dvh - 5rem)` з власним scroll. Footer «Налаштування cookie» відкриває його й переводить фокус на вибір; після вибору фокус повертається. У consent є термін `365` днів; недатований старий запис потребує оновлення. Аналітика до згоди вимкнена, рекламні consent-поля залишаються denied; асинхронний bootstrap перевіряє останній вибір.
- Аналітика дозволена лише на `/uk` та `/en` після acceptance (`isAnalyticsPage`). На документах та auth збір вимкнений навіть за збереженої згоди; банер без вибору там не з’являється самостійно. Footer-control доступний і там. Відмова вимикає collection, а не лише змінює consent flag. Website-choice відокремлений від налаштувань зовнішнього застосунку; технічний inventory описано в `cookies.mdx`.
- Disabled iOS CTA чесно позначає «У розробці». Не давати йому URL і не підміняти статус технічним описом конфігурації.
- За візуальним відгуком від 14.10.2026 під preview залишається лише назва «Картка предмета»: не повертати «Зміни видно одразу» чи декоративний status-dot. Google Play у футері — звичайне текстове посилання без миготливого кружка; іконка недоступного iOS CTA статична.

Форми, auth та юридичні секції мають radius `8px`; demo-frame і schedule `28px`; demo inputs/groups `12–16px`; marketing surfaces `24px` або великі `48px` для фінального CTA; pills `999px`. Межі `1px` із token; тіні — чинні м’які negative-spread, переважно `var(--site-surface-shadow)`. Не уніфікувати ці різні рівні в одну довільну «картку».

Глобальні шари: main `10`, секції/декорація у своїх контекстах `20`, header `50`, cookie `60`, skip-link `100`. Вкладений CTA `z-50` живе всередині своєї секції й не піднімається над глобальним header. Новий dialog, якщо він справді потрібний, повинен мати focus trap, повернення фокуса й Escape; зараз модальних dialog немає.

## Responsive, клавіатура та рух

На телефоні preview та editor — звичайний потік. Не повертати sticky composite із `calc(100svh - 600px)` чи порожній spacer для прокрутки. Обмежений scroll усередині editor фокусується (`tabIndex=0`, labelled region), щоб ним можна було керувати клавіатурою.

Місяць і рік у `FloatingSchedule` переносяться на вузькому екрані; не використовувати `truncate` для поточної дати. Decorative calendar/bell приховані до `sm`, а reset зберігає target `44px`.

Іконки-кнопки та основні дії — мінімум `44px`; icon controls — в обох осях. Документований виняток: сім днів compact-preview ділять доступну ширину телефону, тому ширина окремого дня може бути менша за `44px`; висота `44px`, сусідні дні не перекриваються. `8px` labels weekday/`10–11px` metadata дозволені лише в компактному preview та другорядних підписах; важливі числа/текст поруч більші. Нові форми не повинні копіювати це зменшення.

Глобальний `:focus-visible` — outline `2px`, offset `3px`; editor має синій outline. Не прибирати outline без рівноцінного видимого замінника. Header skip-link веде на фокусований `#main-content`; reader також має `#legal-main-content`. Перевіряти порядок Tab, Enter/Space, Escape та відсутність фокуса у прихованих панелях.

Тема береться з валідного `theme` у localStorage або OS; блоковане сховище не ламає toggle. `ThemeProvider` реагує на media/storage events та прибирає listeners. Не синхронізувати тему через MutationObserver, який бореться з власними оновленнями DOM.

Рух: короткі entrance/hover transitions допустимі, якщо не затримують доступ до змісту. `MotionConfig reducedMotion="user"` спільний; `useReducedMotion` вимикає декоративні loops/tilt та entrance у ключових компонентах. Ribbon при reduced motion показує один статичний набір із перенесенням, без крайових fade. Глобальний CSS зупиняє нескінченні CSS-анімації й smooth scroll. Canvas-компоненти повинні реагувати на media query, зупиняти RAF поза viewport/при прихованому документі та прибирати observers/listeners. Це перевіряти окремо при додаванні нового ефекту.

Zoom: зміст має переноситися, форми залишатися доступними, sticky/fixed-панелі мати вихід через scroll. Не задавати `nowrap` довгим кнопкам і не вважати відсутність document overflow доказом відсутності обрізання дочірнього блоку.

## Українська копія

Сторінка `/{uk,en}/auth/action` підтримує `resetPassword`, `verifyEmail`,
`verifyAndChangeEmail` і `recoverEmail`. Перед підтвердженням або зміною адреси
перевіряється тип підписаного коду Firebase; параметр `mode` не може підмінити
операцію. Зміна email має власні loading/success-повідомлення обома мовами та
оголошення успіху через `role="status"`. Шаблони всіх листів і налаштування
автоматичних повідомлень Firebase належать основному репозиторію PlanIt.

Використовувати «розклад», «заняття/пара» залежно від контексту, «завдання», «оформлення», «вебверсія», «Відкрити вебверсію», «Завантажити з Google Play», «У розробці». Говорити про дію та результат користувача, не про environment variables чи project configuration. Не обіцяти конкретні строки випуску iOS або неперевірені можливості. Нові ключі додавати одночасно в `uk.json` та `en.json`; парність перевіряється тестом. Юридичний переклад береться з наданих користувачем документів головного проєкту; сайт не створює власного перекладу й не видає англійський документ за український.

Команди з кореня (PowerShell):

```powershell
npm.cmd run lint
npm.cmd run typecheck
npm.cmd test
npm.cmd run build
npm.cmd run test:export
npm.cmd start -- 4175
npm.cmd run graphify:update
git diff --check
```

`build` автоматично оновлює legal manifest. `test:export` запускати після build; він перевіряє навігацію, canonical/social metadata, доступність assets, redirects і HTTP-status. Його server-test тимчасово використовує port `4174`. При зайнятому port адаптувати тест явно; не зупиняти невідомий чужий процес.

Social image handlers — статичні GET у `src/app/opengraph-image/route.ts` та `src/app/twitter-image/route.ts`, спільний renderer — `src/components/metadata/OpenGraphImage.tsx`. Metadata явно посилається на абсолютні `SITE_URL/opengraph-image` та `SITE_URL/twitter-image`. Не переносити file-convention image у route group без перевірки URL: у встановленій версії Next він отримує suffix. У static preview та Firebase для extensionless PNG-маршрутів заданий `Content-Type: image/png`.

Кожен навмисний виняток фіксувати тут із джерелом, причиною, областю дії та перевіркою. Якщо поведінка змінилася, оновити посібник і `AUDIT.md` разом із кодом. Не позначати ручну перевірку виконаною, коли був лише source review або інструмент не підтримав потрібний режим.
